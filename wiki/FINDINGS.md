# Wiki.js — реальное приложение, первые находки

Стенд: Lima VM (Ubuntu 26.04, 4 vCPU), Docker, `postgres:15-alpine` + `ghcr.io/requarks/wiki:2`.
`pg_stat_statements` включён. Создано 150 страниц через GraphQL API, затем чтение
страниц нагрузкой через C++-генератор.

## Что видно в pg_stat_statements

| Calls | Всего, мс | Запрос |
|---:|---:|---|
| 152 | 648,1 | `truncate "pageTree" restart identity` |
| 306 | 433,9 | `select * from information_schema.columns where table_name = ...` |
| 51 | 164,3 | `insert into "pageTree" (...) ` — 5100 строк |
| 1734 | 133,4 | `select pages.id, pages.path, ... where localeCode=$1 and path=$2` — 0,077 мс, быстрый |

## Находки

1. **Полная перестройка дерева страниц на каждую запись.** При создании страницы
   Wiki.js делает `TRUNCATE pageTree` и заново вставляет все узлы. Это O(n) работы
   на страницу → рост ~квадратично с числом страниц. На 150 страницах: 648 мс
   суммарно только на truncate. Индексом это не лечится — это архитектурная
   проблема приложения (известная в Wiki.js 2: пересчёт дерева при изменениях).

2. **ORM-интроспекция схемы на каждую операцию.** 306 запросов к
   `information_schema.columns` — 434 мс. Objection.js/Knex перечитывает схему
   таблицы. Кандидат на кеширование схемы в приложении.

3. **Чтение страниц уже быстрое.** Основной SELECT страницы ~0,077 мс — индекс
   по `(localeCode, path)` уже есть, кеширование не нужно.

## Вывод для продукта

Реальный виновник — не «нет индекса», а **паттерн приложения**: частый DDL/TRUNCATE
и интроспекция схемы. Инструмент, который только предлагает индексы, это
проморгает. Анализатор должен также помечать:

- частые `TRUNCATE` / DDL под нагрузкой;
- повторные запросы к `information_schema`/`pg_catalog`;
- паттерн «insert + полная перестройка связанной таблицы»;
- запросы с большим `total_exec_time` при малом `mean_exec_time` (проблема частоты,
  а не одного вызова).

GraphQL-поиск вернул 0 результатов — поисковый движок `db` требует индексации,
которую нужно настраивать отдельно; поисковые запросы в этой сессии не профилированы.
